Om Vercel

Vercel är en plattform som används för att publicera webbplatser och webbapplikationer. Den är anpassad för att kunna publicera projket direkt från ett Git-repository från exempelvis Github. Vercel bygger och publicerar webbplatsen automatiskt och ger den en egen webbadress som sedan går att själv också går att ändra.

Kodstöd och kostnad

Vercel stödjer flera olika tekniker och ramverk. Det går bland annat att publicera webbplatser so använder HTML, CSS, JavaScript och med frontend-ramverk som React, Vue, Angular och Next.js. Det finns även stöd för backend med olika programmeringsspråk och miljöer som exempelvis Node.js och Python.

I den här laborationen har jag använt mig av HTML, CSS, JavaSript och med CSS-ramverken Bootstrap och Tailwind. Vite har även använts som utvecklingsmiljö och det är Distmappen som Vite skapar vid byggprocessen som Vercel använder för att bygga webbplatsen.

Det finns olika prisplaner i Vercel. Hobby är en gratisplan som främst är avsedd för mindre och personliga projekt, men det finns även en betalversion för större och mer avancerade projekt. För denna lilla laboration räckte dock gratisversionen väl.

Fördelar och nackdelar

Fördelar

  • Det är enkelt att koppla ett projekt till GitHub och publicera direkt från plattformen.
  • Vid användning av Vite känner Vercel av detta och anpassar inställningarna inför publicering automatiskt för detta.
  • Enkelt gränssnitt att förstå för att publicera.
  • Publiceringen sker automatiskt när nya ändringar görs i det anslutna Git-repot.
  • Vercel skapar en webbadress som gör webbplatsen tillgänglig på internet.
  • Det finns en kostnadsfri plan som fungerar bra för mindre, personliga projekt.
  • Det går att se loggar för publiceringen och kontrollera om publiceringen har lyckats.

Nackdelar

  • Projektet behöver vara korrekt konfigurerat för att byggas och publiceras.
  • Gratisversionen har begränsningar och är inte avsedd för större projekt eller kommersiell användning.
  • Om något blir fel under byggprocessen kan det krävas felsökning innan webbplatsen kan publiceras.

Publiceringsprocess

För att publicera webbplatsen började jag med att skapa ett konto på Vercel och koppla det till mitt GitHub-konto då detta är första gången jag testar på att publicera på denna via Vercel. Därefter importerade jag projektets repo från Github och kontrollerade inställningarna för bygget. Vercel gav mycket gratis vid inställningarna då det automatiskt anpassade dessa för Vite som använts i projektet.

Eftersom projektet använder Vite angas npm run build som byggkommando och dist som mapp för de färdiga filerna. När inställningarna var klara startade jag publiceringen med Deploy.

Efter att webbplatsen hade publicerats skapade Vercel en webbadress som jag kunde använda för att besöka den färdiga webbplatsen. Jag testade även att navigeringen och utseendet fungerade på samtliga sidor. Själva publiceringen gick igenom utan fel men på grund av felplacerad JavaScript behövdes ändringar göras i koden för att sidan skulle fungera helt felfritt.

En fördel med arbetssättet att använda sig av plattformar som Vercel är kopplingen direkt till GitHub. När ändringar görs i projektet skickas dessa via GitHub, och då startar Vercel automatiskt en ny publicering. Det innebär att man inte behöver ladda upp filerna manuellt varje gång.
